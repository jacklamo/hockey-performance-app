## v2.0 Requirements (All Complete)

### UX Polish

- [x] **UX-01**: User sees a logout button on every protected page that ends their session and redirects to /auth/login
  - **Outcome:** Partially satisfied. Header.tsx with Logout wired to /dashboard, /games, /games/[id]. NOT wired to /games/add, /games/[id]/edit, /games/[id]/mental. Accepted as known gap.

- [x] **UX-02**: User sees a skeleton loading UI (not a blank screen) during initial page load on /dashboard, /games, and /games/[id]
  - **Outcome:** Fully satisfied. Three route-level loading.tsx skeletons using CSS shimmer animation. Server Components — no client bundle impact.

- [x] **UX-03**: User sees a loading indicator on submit buttons during form mutations (add game, edit game, log mental state, delete game) and the button is disabled to prevent double-submit
  - **Outcome:** Fully satisfied. Loader2 spinner + disabled state on all 4 form actions. PDF import label also gets spinner.

- [x] **UX-04**: User sees an informative empty state (not a blank area) when they have no games logged
  - **Outcome:** Fully satisfied. /games shows ClipboardList icon + "Add Your First Game" CTA when games array is empty.

- [x] **UX-05**: User sees a graceful error UI with a retry option when /dashboard or /games fails to load data
  - **Outcome:** Fully satisfied. AlertCircle inline error card with retry button calling fetchGames() directly — Header always visible in error state.

### NHL Pipeline

- [x] **PIPE-01**: Pipeline walks a full NHL season's date range and collects all gameIds via the schedule endpoint
  - **Outcome:** Fully satisfied. `fetch_game_ids(season)` walks SEASON_DATES day-by-day, filters gameType==2, deduplicates, returns sorted list.

- [x] **PIPE-02**: Pipeline fetches play-by-play for each game and filters to shot events (shot-on-goal, goal, missed-shot, blocked-shot)
  - **Outcome:** Fully satisfied. `fetch_shots(game_id)` extracts SHOT_TYPES plays with null-safe details and scoringPlayerId fallback.

- [x] **PIPE-03**: Pipeline inserts shot events into a `nhl_raw.shot_events` table in Postgres with idempotent upsert (no duplicate rows on re-run)
  - **Outcome:** Fully satisfied. ON CONFLICT (game_id, event_id) DO NOTHING. Idempotency confirmed: 0 new rows on second run of same date range.

- [x] **PIPE-04**: Pipeline rate-limits requests (~1 req/sec), retries on 429/503 with exponential backoff, logs failed games without crashing the run, and outputs a post-ingestion row count
  - **Outcome:** Fully satisfied. `_get()` with tenacity (3 attempts, exponential backoff). Failed games log [SKIP] and continue. Post-run summary printed to stdout.
